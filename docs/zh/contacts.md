# 接触与闭链 {#contacts}

这个库里"接触"有两个含义，做的是两件事。选错那一个，是拿到"看起来合理但是错的"数字
最常见的原因。

| | |
|---|---|
| rd_rnea_ext()、rd_aba_ext() | 你已经知道并且正在施加的力：测力计读数、载荷、推进器 |
| rd_constrained_dynamics() | 一只踩住了、不允许加速的脚。它的力从 `lambda` 里出来 |
| rd_constrained_dynamics_ext() | 两者同时，一个背着东西站着的机器人需要的就是这个 |

## 一个你已经知道的力

rd_rnea_ext() 和 rd_aba_ext() 每个**连杆**收一个空间力，在该连杆自己的体坐标系下，
并把它折进 O(n) 递推里。所以一个接触的代价是几次加法，而不是每个接触一次雅可比转置。

```c
rd_real_t f_ext[6 * RD_MAX_LINKS] = {0};
/* 世界系下作用在连杆 i 原点的力 w： */
rotate_world_to_body(&T_i[0], w, &f_ext[6*i]);
rd_rnea_ext(&chain, &state, qdd, NULL, f_ext, tau);
```

把力放在脚上是有效的，即使脚通常是被 rd_chain_build() 折走的固定连杆：这个数组按连杆
索引，而那次折叠会把力连同惯量一起带到可动祖先上。

没有受力的连杆每个只花六次比较，传 `NULL` 则完全不花。

## 一只踩住了的脚

一只踩住的脚是一个**约束**。你不知道它的力；你知道它的加速度是零，而力是解出来的结果。

URDF 是一棵树，说不了机器人身上有个闭环，所以闭环按 Pinocchio 的方式声明：保留模型
本来就是的那棵树，然后约束它被剪开的那两个 frame。同一个对象也用来把脚钉在地面上，
第二个 frame 写世界。

```c
rd_constraint_t con[2] = {
    { fl_foot, RD_ANCHOR_WORLD, RD_CONSTRAINT_POINT },   /* 一只脚踩住   */
    { link_a,  link_b,          RD_CONSTRAINT_FULL  },   /* 一个五连杆闭合 */
};

rd_int_t nw = rd_constrained_dynamics_work(&chain, con, 2);
static rd_real_t work[NW_MAX];
rd_real_t lambda[6];

rd_constrained_dynamics(&chain, &state, tau, NULL, con, 2,
                        work, qdd, lambda);
```

约束是参数而不是 chain 的一部分，因为足式机器人每抬一次脚接触集就变一次。抬腿在下一个
周期就是一个不同的数组，不重建也不分配。

@warning `frame_b` 是一个索引，表示"世界"的值是 RD_ANCHOR_WORLD，即 `-1`。
在那里写 RD_FRAME_WORLD 能编译通过，因为那是一个取值为 `0` 的 rd_frame_t，
于是脚被安静地约束到 0 号连杆 —— 基座。然后脚跟着身体一起动，求解返回的数字看起来
还挺像样。见 @ref conventions "约定"。

## 它解的是什么

KKT 系统，M 只分解一次：

```
[ M   Jᵀ ] [  qdd  ]   [ tau - h ]
[ J   0  ] [ -λ    ] = [ -gamma  ]
```

`J` 是约束雅可比，`gamma` 是让约束在加速度层面保持满足的偏置项。
rd_constraint_jacobian() 和 rd_constraint_bias() 也是公开的，
供想自己组装 KKT 或者在上面搭接触求解器的人用。

各行写在 `frame_a` 原点处的世界系对齐坐标轴下，`lambda` 也回到同一组轴上。
RD_CONSTRAINT_POINT 三行，RD_CONSTRAINT_FULL 六行；rd_constraint_rows() 帮你加起来。

## Go2 例子里的四件事

`examples/go2_contact/` 在一台四足上把这套东西从头跑到尾。`make && ./go2_contact`，
除了这个库和一个生成好的 Go2 模型之外什么都不需要。

**约束按住的是脚，不是机器人。** 四只脚全踩住、关节力矩给零，身体照样以接近一个 g
往下掉。脚没动，膝盖折了，地面只提供了 158 N 体重里的 10 N。站起来是个力矩问题；
接触只负责告诉你地面回给了多少。

**选多大的足底力是调用方的事。** 把体重平均分给四只脚，用 rd_rnea_ext() 问在这组力下
保持静止需要多少力矩，回来的前六行不是零 —— 浮动基座没有驱动器，那六行里剩下的就是
"平均分"没能达到的那个平衡条件。把它压到零叫力分配：一般是个小 QP，是个控制决策，
而且刻意不放在这个库里。就这么把力矩发下去，基座的高度加速度保持在 0.06 m/s²，
俯仰是 5.8 rad/s²，那正是那个残差变成了运动。

**支撑集和力矩要一起变。** 拿四脚算出来的力矩去发给只有两只脚着地的姿态，一半体重
就没人扛。按实际着地的脚重新分配之后，地面又扛住了全部 158 N。

**摩擦锥才是这件事变成接触动力学的地方。** rd_constrained_dynamics() 解的是一个*等式*
约束系统。为了维持约束，它会把脚往下拽，也会索取任意大的切向力。让脚把机器人往侧面推，
切向需求随加速度上升，而法向力被体重钉住；超过 μ·g 之后，力矩说什么都送不出去。
检查法向力为正、切向力落在锥内是调用方的事，因为强制它是一个迭代过程 ——
把不满足的脚释放掉再解一遍 —— 而用哪种迭代是个控制决策。

## 自己跟自己对账

正向求解出来的那组力，再喂回 rd_rnea_ext()，能复现出它一开始的那组力矩。
Go2 例子里这个来回闭合到 1.5e-05。

这个检查不需要参考实现，也不需要 Pinocchio，而符号错了或者参考系错了就会在这里暴露。
值得接进你自己的调试流程。

## 代价

STM32L413 @ 80 MHz，Go2，`update_kinematics` 加上求解：

| | |
|---|---|
| 无接触（`rd_forward_dynamics`，CRBA） | 435 µs |
| 两个点接触 | 1039 µs |

大约 2.6×。多出来的是约束雅可比、偏置项，以及每个约束行一次 Cholesky 回代 ——
两个点接触就是六次。质量矩阵两种情况下都只分解一次。

## 带减速比的关节

它不是接触，放在同一段里说是因为它改动的是同一组方程。`armature` 是折算转子惯量，
`n²·I_rotor`，在舵机或任何高减速比驱动上，它经常比它转动的那根连杆还大。

URDF 里没有这个字段，所以转换出来的模型从零开始，由 rd_chain_set_armature() 填。
它被 rd_crba() 加到 `M` 的对角上，被 rd_rnea() 加到 `tau` 上，被 rd_aba() 加到关节体
惯量上，三者因此保持一致。没有设过它的模型会跳过这部分工作：走一遍对角线要花
rd_crba() 的 3–5%，所以 chain 记着有没有任何关节设过。
