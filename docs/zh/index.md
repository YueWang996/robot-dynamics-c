# RobotDynamics {#mainpage}

*装得进单片机的刚体动力学。*

C99，除 `libm` 之外零依赖，在一块五美元的板子上给 18 自由度四足机器人跑
1 kHz 力矩环。

给它一个从 URDF 转出来的模型和一块缓冲区，它返回力矩、雅可比和质量矩阵，
快到可以在机器人自己身上闭环。这里没有控制器，也没有接触求解器：你拿到的是
M、h、J、J̇q̇ 和一份分解，在上面搭什么是你的事。

## 里面有什么

| | |
|---|---|
| 算法 | 正运动学、几何雅可比、RNEA、ABA、CRBA、重力项、科氏项与非线性项、空间速度与加速度 |
| 关节 | 转动、移动、固定，以及浮动基座 |
| 参考系 | 凡是涉及参考系的地方都支持世界系和体坐标系 |
| 接触 | 任意连杆上的外部空间力，在 O(n) 递推内部施加 |
| 约束 | 落地的脚，以及树被剪开处的闭链，作为 KKT 系统求解 |
| 驱动器 | 每个关节的折算转子惯量，任何带减速比的驱动都需要 |
| 线性代数 | 正动力学用的那个 Cholesky，公开出来供任务空间使用 |
| 精度 | 对照 Pinocchio 验证：float64 达 5.5e-15，float32 达 1.9e-06 |
| 数据类型 | 默认 `float`，一个开关切到 `double` |
| 内存分配 | 控制环内不分配。所有算法的临时空间共用一块由调用方提供的缓冲区 |
| 依赖 | `libm`。就这一个 |
| 体积 | 整库 40.2 KB 的 Cortex-M4 代码，`--gc-sections` 丢掉没调用的之后约 25 KB |
| 分发 | 单个头文件 |
| 模型来源 | URDF，经 `tools/urdf2c.py` 转换 |

一个控制周期通常要同时算好几个量，而每一个都要先走一遍运动学树。
rd_update_kinematics() 只走一遍，后面所有算法读这份缓存，速度主要就来自这里。

@note 尚未到 1.0，有三处值得先说清楚。移动关节已实现但未验证，因为参考机器人全是转动
关节。关节限位、阻尼和摩擦会被解析并保存，目前还没有算法读它们。rd_chain_build()
在启动时分配一次，所以真正无堆的构建暂时做不到；无论如何控制环内不分配。

## 来历

为 [SPARC](https://github.com/YueWang996/sparc) 而写 —— 一个用于四足机器人的三自由度
矢状面脊柱单元。脊柱既给动力学模型加自由度，又把控制环收紧，这两个要求同时压过来，
就是这个库被塑造成现在这样的原因。

设计上取自 [bard](https://github.com/YueWang996/bard-pytorch-dynamics)，那是这个库在
PyTorch 一侧的对应物。模型与数据的切分、算法集合、`q` 的排布、空间代数的约定都来自
那里，所以在工作站上对着 bard 训出来的策略，可以在机器人上对着这个库跑。

正确性对照 [Pinocchio](https://github.com/stack-of-tasks/pinocchio) 测量，算法是
Featherstone 的。
